# 绿色版与数据目录

这份文档专门说明「软件把东西存在哪」，以及怎么备份、迁移、清理。

---

## 1. 一句话版本

> 所有数据都在 exe 旁边的 `data` 文件夹里。程序不写 C 盘，不写注册表，不写 `%APPDATA%`。

---

## 2. 目录约定

```
暮呈照片水印工作台/
├─ 暮呈照片水印工作台.exe        主程序
├─ WebView2Loader.dll           必需运行时（勿删）
├─ 使用说明.txt
├─ LICENSE
└─ data/                        首次运行自动创建
   ├─ config.json               全部设置
   ├─ logs/
   │  └─ app.log                运行日志
   └─ webview/
      └─ EBWebView/
         ├─ Default/            WebView2 profile
         │  └─ Local Storage/   localStorage（运行时缓存）
         └─ Local State
```

`data/webview` 下为什么还套一层 `EBWebView`：我们把 `data/webview` 作为 WebView2 的
user data folder 传进去，WebView2 会在此之下建自己的 `EBWebView` 目录。这是组件的固定
行为，不是重复。

---

## 3. 路径是怎么来的

`src-tauri/src/paths.rs` 里只有一条推导链：

```
app_root()   = std::env::current_exe().parent()
data_dir()   = app_root() / "data"
config_file()= data_dir() / "config.json"
log_dir()    = data_dir() / "logs"
webview_dir()= data_dir() / "webview"
```

代码中没有出现任何盘符或绝对路径。程序被移动到任何位置（D 盘、U 盘、网络盘），
数据目录都会跟着走。

**两个调试用覆盖项**（属于显式覆盖，不是硬编码）：

| 环境变量 | 作用 |
| --- | --- |
| `ECW_ROOT_DIR` | 覆盖「软件根目录」 |
| `ECW_DATA_DIR` | 覆盖「数据目录」 |

例如把数据放临时盘做测试：

```bash
set ECW_DATA_DIR=E:\wm-test
暮呈照片水印工作台.exe
```

---

## 4. 启动时会检查什么

1. `data/`、`data/logs/`、`data/webview/` 是否存在，不存在就创建
2. 往 `data/.write-test` 写一个探针文件，确认目录**真的可写**（不只是能建目录）
   - 失败 → 弹窗提示「请把程序放到有写入权限的位置」后退出
3. 若检测到旧版数据目录（`%LOCALAPPDATA%\com.linghang.exifcam\EBWebView`）且尚未迁移，
   只读复制一份到 `data/webview/EBWebView`，写标记 `.migrated-from-legacy`
4. 若 `config.json` 不存在，生成一份带说明的空文档
5. 以 `data/webview` 为 user data folder 创建主窗口

任何一步的状态都会写进 `data/logs/app.log`，出问题时先看它。

## 5. config.json 结构

```json
{
  "schema": 1,
  "app": "暮呈照片水印工作台",
  "savedAt": "2026-11-02T04:42:23Z",
  "note": "本文件由程序自动维护……",
  "kv": {
    "ecw.cfg.v4": "{...全部水印参数...}",
    "ecw.theme": "dark",
    "ecw.uiColor": "#4F6BED",
    "ecw.presets.v1": "[...自定义预设...]",
    "ecw.brandLogos.v1": "{...}"
  }
}
```

- `kv` 里的键就是前端使用的 localStorage 键名，值为字符串
- 写入是「临时文件 + 原子 rename」，断电不会留下半个 JSON
- 解析失败时会把坏文件另存为 `config.json.broken`，并回退到空配置

**运行时关系**：localStorage 是运行时缓存，`config.json` 是权威快照。启动时以快照回填，
所以强杀进程也不会丢最后一次改动。

## 6. 备份与迁移

**完整迁移（推荐）**

关掉软件 → 复制整个文件夹 → 在新机器上打开 exe。

**只迁移设置**

把 `data/config.json` 放到新目录的 `data/` 下（没有就新建），首次启动会自动回填。

**只还原某几项**

用文本编辑器打开 `config.json`，把 `kv` 里对应项的值改掉，保存后重启即生效。
注意值本身是**字符串化的 JSON**，里面引号要转义；不确定就先在软件里改一遍再对照。

---

## 7. 清理

| 目的 | 做法 |
| --- | --- |
| 清日志 | 删除 `data/logs/` |
| 重置设置 | 删除 `data/config.json` |
| 彻底重置（含缓存） | 删除整个 `data/` 文件夹 |
| 清理旧版残留 | 删除 `%LOCALAPPDATA%\com.linghang.exifcam`（旧版数据，本程序只读不写） |

删除 `data/webview` 后首次启动会慢几秒（WebView2 要重建 profile），属正常。

---

## 8. 为什么不用系统默认位置

Tauri / WebView2 的默认行为是把用户数据写到 `%LOCALAPPDATA%\<identifier>\EBWebView`。
那样一来：

- 绿色版就名不副实（拷走文件夹也带不走配置）
- 卸载残留需要用户自己去系统目录翻

本程序在主窗口创建时显式传入 `.data_directory(<数据目录>/webview)`，把 WebView2 的
用户数据目录钉死在软件目录里。这是「不写 C 盘」这一条能成立的关键。
